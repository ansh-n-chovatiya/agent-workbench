# Brief S6 part 2: offline mix with ducking, then loudness
You are a delegate. Claude reviews your work and re-runs your numbers, so report only what commands printed; never invent a figure. Work only under `spikes/showreel/`. No git commands. Do not touch `docs/` or `plugins/`. Run measurements alone (no other heavy processes). If a command is blocked or fails, report the exact error and stop that part; a failed attempt is a valid result.

Prerequisite: `s6-loudness/lufs.mjs` exists and its tests pass (another delegate is writing it; if it is missing, stop and say so).
Create `s6-loudness/mix.mjs`: run Chromium via Playwright (page served from `http://127.0.0.1`), build an `OfflineAudioContext(2, 48000*20, 48000)` containing: two narration clips (a 220 Hz tone burst with a 30 ms fade in and out, clip 1 at 2.0 to 5.5 s, clip 2 at 9.0 to 13.0 s, each about -20 dBFS), a music bed (a 110 Hz tone plus a 220 Hz tone at -26 dBFS for the full 20 s) through a `GainNode` that ducks to 0.25 during each narration clip (`setValueAtTime` and `linearRampToValueAtTime`, 150 ms attack, 400 ms release). Render, return the two channels to Node, then with `lufs.mjs`: measure integrated loudness, compute `gainToTarget(measured, -16)`, apply it, re-measure. Also measure the music-only level during a narration clip and between clips (RMS of the rendered signal minus the narration, or render the music alone as a second offline pass) to show the ducking depth in dB.
Write `results/s6-loudness.json` { measuredLufs, gainDb, afterGainLufs, withinOneLU, duckingDepthDb }. Done when the file exists and the final message lists the commands and JSON. Do not modify lufs.mjs or its tests.
