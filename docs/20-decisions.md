| D18 | **Quality is a fixed requirement. Opus stays the default model.** Savings come first from context hygiene (fresh sessions at stage boundaries on the same model, `/clear` between units), removing wasted review runs (D16, D17), trimming tool output, warm subagent caches and per-project skill sets. A model downgrade ships only after a **quality gate**: the same real change run on both models shows findings per round, rounds to approval and escaped bugs equal or better. `opusplan` is not used (every plan-mode toggle rebuilds the cache; ctx does not use Claude's plan mode). **Stage-based model plan (owner approved 2026-10-17):** spec, plan, design, review and the final PR check on Opus; build (unit-runners) and orchestration on Sonnet **if and only if the quality gate passes**, with Sonnet as the default for those stages from then on ("if Sonnet can do it accurately, so be it"). Until the gate passes, every stage stays on Opus. ctx prints a one-line stage hint (for example "Build stage: Sonnet recommended, start a fresh session") and never switches a running session; it ships default off until the gate passes. First step: explain why unit-runners ran on Opus although `models.runner` is sonnet (Q17), which may already be the cheapest saving. Goal stated by the owner: lowest token use at the highest accuracy that the evidence supports. Safest downgrade candidates first: read-only Explore and lookup agents. Reviewers, spec and design stay on Opus. | About 80% of tokens are main-chat cache reads and about 97% of main requests ran on Opus; the owner will not accept lower output quality. | 19, 16 | decided by owner (quality first); gate details proposed |
| D19 | **Read the existing "model-router" plugin and local mods before writing `ctx-optimize`'s router.** Extend or replace on evidence. | The owner already runs one (Q15). | 19 | proposed |
| D20 | **Ship changes directly to Context Ledger, all features on by default, each with a config switch to turn it off.** Order of work: each feature is built behind its switch **default off**, measured against the quality gate (D18), then flipped to default on; this avoids a loop where a feature must be on to be tested and tested before it is on. The quality gate (D18) still decides any model downgrade. | The owner is currently the only user of ctx and the other tools. | owner statement | decided by owner |
| D21 | **Setup enforces the core defaults and asks only what depends on the machine or project** (which optional agents are installed, whether to merge base settings after a diff, a new project's own rules). `--yes` accepts every default. Setup is idempotent and never asks for or stores secrets. | One-command setup on any PC, with minimal questions. | 21 | proposed |
| D22 | **Terse subagent reports, built by us, not the Caveman plugin.** A short "reply briefly, keep file:line evidence, severity, numbers and negations exact, full sentences for warnings" rule goes into ctx's own subagent prompts. **Subagents: always on, at the strongest level we define** (owner decision 2026-10-17); the strongest level shortens wording and structure but never drops a required field (severity, `file:line`, reason, evidence for findings; criteria met or missed for builders). **Main thread: on by default at a "standard" level** (owner decision 2026-10-17): plain complete sentences, human readable, no preamble, filler or recap, short lists where useful, reasoning and risks still explained in full; not the telegraphic style. A `ctx.yaml` switch turns it off or raises the level. Mechanism for non-ctx subagents: the mod prepends the rule to the spawn `prompt` (verified in the type file); for ctx's own agents the rule lives in their prompt files. Our own level definitions, not Caveman's (its strongest mode includes non-English output). It ships on by default only after the quality gate (D18) shows findings are no worse. Do not install Caveman, its proxy or its Auto routing. | Subagent reports are re-read by the main chat on every later request. The plugin's Auto routing sends prompts to a third-party cloud (breaks the no-outside-service rule) and its proxy is a gateway (D5). Its rules are Apache-2.0 and can be adapted with a notice. | 12, 16, 19 | proposed |
| D23 | **Scope discipline: add a short global "stay inside the task" rule to the profile's global instructions**, keep ctx's existing scope checks unchanged, and measure unrequested-change findings before adding anything mechanical. Rule text and acceptance in 23. | Over-engineering is a general model habit, wastes tokens and enlarges reviews; a few lines cost almost nothing. | 19, 22, 23 | decided by owner (rule text still to be tightened, Q20) |
| D24 | **Release, licence and rollback are part of the plan:** per-plugin versions and tags with CI refusing an unbumped release; one top-level licence plus notices (`ai-skills` currently has none, add MIT with the owner's confirmation); every default-on feature has a switch and a test that proves the off state. Details in 30. | A public multi-plugin repo needs predictable updates, a clear licence, and a way back. | 17, 30 | proposed (licence choice needs owner confirmation, Q21) |

## Changes to the seed spec (`_seed-claude-token-router.md`)

1. Env var `CLAUDE_CODE_SUBAGENT_MODEL` no longer outranks the mod unless `_FORCE=1` is set (10).
2. Working title "Claude Token Router" cannot be a plugin name (D13).
3. Shared-store concurrency is solved by `$.store` (10).
4. Keyword rules become a fallback, not the primary router (D8).
5. "No network, no shell" for the mod is unverified; the API lists `$.http` and `$.process` (10, Q3).
6. Added: tokens are reported by stage and by ledger unit (11, 21).
